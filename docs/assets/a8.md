## Round 3 review fixes

1. `sfx_synth.gd:223`: removed the 20 ms decay cap. Each percussive body now uses
   `duration * 0.16`, preserving weight throughout its authored length. A separate 4 ms
   contact transient (`click_transient`) sits outside that body envelope. Boss hit and caught
   add a falling 65 to 40 Hz sub thump whose decay follows the body instead of a fixed timer.
   Headless assertions check the duration-scaled envelope, rendered RMS during 20-40% of
   each impact, the sub's sustained energy, and the click's independent four-millisecond cutoff.
2. `sfx_synth.gd:39`: `tool_fire` now belongs to the percussive family, with a 1.5 ms body
   attack and the separate click. Its existing 0.10 s scheduling offset is unchanged.
   The rendered-buffer test requires the first 15 ms to reach at least 80% of the whole cue's peak.

Additional improvements:

- Panned whooshes retain both authored stereo channels, applying directional gains without
  downmixing. Center-pan PCM must match the original exactly; directional tests preserve the
  near-side channel. This chooses the review's stereo-preservation option and keeps the
  existing stream-based API and cached PCM budget.
- DC window values and their sum are computed once per buffer and reused across channels.
  `bind()` prewarms the cached boss intro before it can first trigger in a fight.
- Jump uses a short tonal decay with zero noise bed. Pursuit start has an initial strike
  followed by a rising second stage and release. Envelope assertions cover both profiles.
- `play_ui_click()` is explicitly a gameplay-only audition stub. It remains pause-gated;
  pause-menu UI must continue using `AudioService.play_ui`. Wiring UI is outside A8 ownership.
- Kept explicit PAUSABLE players to satisfy the asset requirement, alongside the existing
  signal-driven `stream_paused` handling used by facade/mock pause transitions.

Round-3 edits: `sfx_synth.gd`, `runner_audio.gd`, `tests/assets/a8_check.gd`, and this report.
No graphical scene was run; coordinator previews were not modified.

## Round 2 review fixes (retained, with round-3 envelope refinement)

1. Looping cues bypass the edge fade (`sound`). Tests check wrap delta below 0.015
   for all three loops and compare the drone's final 132 samples to its unfaded layered waveform.
2. `footstep(surface, variant)` has separate cache and seed axes (`footstep`).
   Both variants keep the selected surface filter; tests check distinct seeds, PCM, and cache identity.
   `runner_audio.gd` passes `_surface` and `_tread % 2` separately.
3. Bus acquire moved to `_enter_tree()` (`runner_audio.gd:56`), paired with `_exit_tree()`.
   A remove/re-add test verifies bus recreation, valid player/whoosh routes, then rebinds.
4. Percussive cues use a 1.5 ms attack and duration-scaled exponential decay
   (the round-2 20 ms cap was removed in round 3). Chimes ring with exponential release; whooshes swell; alarms sustain.
   Tests assert short percussive tails and a retained musical ring.
5. Five family-specific layer mixes replace the shared formula (`LAYERS`). Chord,
   sine and arpeggio cues have zero noise weight. The drone combines 55 Hz body, 57 Hz detune
   and 27.5 Hz sub with integral cycle counts (`drone_sample`). Tests check tonal noise
   weights and the final drone samples against the full layered signal.
6. Family, waveform, directional-pan and sting flags are resolved before the sample loop
   (`sound`). Arpeggio intervals are constant. The source assertion prevents
   reintroducing the reviewed per-sample array expressions.

All suggested improvements were implemented. Raw peaks are measured before any correction;
a separate saturation burst reaches exactly ten voices without clearing the pool between cues.
Intro sub restarts at 2.4 seconds and alert sub restarts on every gate, with direct assertions.
Delay uses typed setter methods (Godot exposes slash-named inspector properties), with assertions
for both times, levels, pans, and disabled feedback. Footstep state uses PackedFloat64Array.
The optional UI hook remains documented for A7 integration because UI files are outside A8 ownership.

## Sound design

All 32 recipe keys, durations, gates, priority tiers, the seven-plus-three voice layout,
radar-to-heartbeat handover, directional whooshes, and music duck/pitch behavior remain intact.
Cached deterministic PCM combines the authored event contour with detuned oscillators,
FM transients, filtered noise sweeps, sub-weighted impacts, family-specific envelopes, and recipe-specific
stereo widths. Looped cues remain mono to preserve the existing loop contract; their periodic
layers preserve wrap continuity without an edge fade. Only non-looping cues fade at endpoints. DC correction uses a zero-ended window.
PCM normalization only attenuates, with a 0.79 ceiling and no loudness boost.

Footsteps alternate cached tread variants. The optional `set_footstep_surface(0..2)` hook
selects metal, grating, or rubber coloration without inventing a backend surface signal.
The optional `play_ui_click()` hook reuses the short telegraph tick through the existing
voice pool during unpaused gameplay only. It is an unwired audition stub, not a pause-menu
click implementation. Existing UI AudioService calls are untouched.

`RunnerSFX` is created at runtime with a small-room reverb (10% wet) and a gentle
2.2:1 compressor at -10 dB. The SFX bus sends through it, keeping the existing four
players' `SFX` labels and shared volume control. A `RunnerWhoosh` bus adds quiet left/right
74/148 ms taps to turn/projectile whooshes and Nitro before sending to SFX.
The temporary SFX send affects all other SFX, including AudioService.play_ui, while a runner audio mount exists.
Shared leases allow overlapping mounts. Final teardown restores the original SFX send and
removes both temporary buses. AudioService still owns exactly two players.

The root retains the contract-required ALWAYS mode for pause signal handling; its four
players are explicitly PAUSABLE. Existing manual pause/gating logic is preserved.
No shaders, textures, particles, collision shapes, or gameplay geometry are introduced.

## Host capture and listening

```sh

```

The capture script creates a 1280x720 corridor-style diagnostic fixture with gameplay-distance,
close-up, and intro waveform views. It writes `docs/previews/assets/a8-gameplay.png`,
`a8-closeup.png`, and `a8-intro.png`, reports actual render draw calls per view, then prints
`ASSET A8 CAPTURE: PASS`. Fixture geometry is diagnostic, not part of the audio asset budget.
Headless invocation was verified to exit 1. No graphical capture or listening judgment is claimed.
For an audible review use the runner preview or game to hear the full recipes; captures are quick
waveform snapshots and are not an audio export. Host listening should assess transient clarity,
stereo translation, loop transitions, effects tails and the ten-voice combat mix with BGM.
