## How to rebuild

Blender must run on the host; it crashes in the sandbox. From `hoppys-adventure-arcade/`, rebuild the GLB, render the front/three-quarter/rear turntables, then import into Godot:

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --python-exit-code 1 --python tools/blender/rebuild_hoppy.py -- --out Assets/runner/hoppy/hoppy.glb
/Applications/Blender.app/Contents/MacOS/Blender --background --python-exit-code 1 --python tools/blender/render_hoppy.py -- Assets/runner/hoppy/hoppy.glb /tmp/hoppy-turntables
/Applications/Godot.app/Contents/MacOS/Godot --headless --log-file /tmp/a1-import.log --path . --import
```

## Character and runtime

`tools/blender/build_hoppy.py` authors the original character, quad-ring subdivided limbs, blended joint weights, expressive face, bent ears, hoodie/hood/pocket/cuffs, embossed braces, piping, goggles, wrist screen, battery pack and sneakers. Body textures are 2048 square; accessory textures are 1024 square. `glb_atlas.py` shares eight atlas images/texture entries, including one ORM texture per atlas referenced by both occlusion and metallic/roughness. The accepted round-6 bake includes rounded soles, a deeper hood and corrected palette and brace marks.

`hoppy_runner_visual.tscn:3` instances the imported GLB under `Root/Model`. `hoppy_runner_visual.gd:34` uses the imported Skeleton3D and AnimationPlayer, duplicates clips/materials per instance, and restores the public AnimationPlayer path with the imported animation root preserved. Its seven actions are idle/run/fall loops and jump/roll/hurt/dead one-shots. Cross-fades are 0.08 seconds, with zero blend entering/leaving roll. One-shots hold their final pose until the backend requests another state; hurt alone returns to the previous locomotion state after its 0.6-second action. No backend behavior was changed.

`hoppy_runner_visual.gd:120` retains all six contract hooks. Normalized run speed is clamped to 0..1 and maps to 0.9..1.6 animation speed. Root Z lean remains -direction * 0.12. `hifi/lane_look.gd:1` applies a small head yaw after animation evaluation. Hit flashes tint private material copies instead of adding a full-character overlay pass. The retained hex shader drives shield/aura shells centered from the chest bone; their roll radius/center stay inside 0..0.9 m. MATRIX glyphs emit from the animated hood position at speed. All cosmetic nodes are PAUSABLE with interpolation OFF.

## Import and files

Default GLB scene import produces a Skeleton3D, 27 bones, two mesh nodes with three material surfaces, and seven actions. Godot's default embedded-image handling extracts eight `hoppy_*.png` files used by the imported scene. Those eight files and their `.png.import` descriptors are part of the change, along with `hoppy.glb.import`. Their texture imports use `compress/mode=0`, `vram_texture=false`, and mipmaps. A1 verifies those lossless settings and atlas size caps under the Compatibility project renderer.

Round 6 removes the eight redundant inspection PNGs and `source/.gdignore`. The GLB embeds eight images; the eight Godot-extracted `hoppy_*.png` files are the runtime copy and remain inspectable. There is no third copy in `source/` or beside the GLB under the original bake basenames. The build sidecar still lists those image basenames as metadata, without requiring redundant files. No external assets are downloaded. `Assets/runner/LICENSES.md` records original in-repo work under the project licence.

The `tools/blender/rebuild_hoppy.py` host entrypoint runs the build recipe, verifies the embedded GLB through that recipe, then deletes only its exact loose PNG filenames from the sidecar. It suppresses only Blender 5.2's exact redundant sampler notice. Inspection of the installed exporter showed that it warns on socket count even when the roughness and metallic sockets resolve to the same image node. All other warnings/errors remain enabled. The wrapper filter passed a plain-Python check. The coordinator completed the host rebuild; the shipped GLB, sidecar and recipe provenance checks pass in A1.
